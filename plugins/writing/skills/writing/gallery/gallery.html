From artifacts.md, section "Mark"

A mark gives the state of an item. It is the mark of the stream tracker.

PartValues
Color: healthdone green, prog blue (in progress), you amber (waits for you), blocked red, plan purple (planning), none grey (not started)

4 · Draft rule
From artifacts.md, section "Foldable list"

One component for all lists of items: findings, decisions, proposals, questions and plan phases.

PartRule
BoxOne box for each item, with a gap between
Title6 words maximum, one line, cut with "…" when closed
Key factOptional second line, 13px grey
IDOnly when readers refer to items by ID: K1, Q1, P3
StateOne mark at the right. References as chips, up to 3
Open contentFull width, under a line
SizesTitle 15 bold, key fact 13, ID 12 code font, chip 11 code font
  • Put a table or a diagram of all items before the list.
  • Keep the items closed. Do not put the main message or a warning in an item.
  • Nested items: an open item can hold a child list (.fl in .body). The children show as boxes on a grey area. 3 levels maximum.
  • Groups: split a long list into one parent item for each group, for example "Gaps". The key fact gives the count: "9 items".
  • Sections: split a long item into parts, each with a .lbl label above it: "Where", "Why it matters", "Fix". All items of one list use the same labels, in the same order.
  • Rich content: text, tables, code blocks and notes use the full width of the item.
  • Length: about 300 words in one item. If an item is longer, split it into child items, or give it its own tab.
  • Question: ID Q1, key fact "Default: …", mark you ? while open, mark done ✓ when answered.
  • Plan phase: ID = phase number, key fact = decisions and issue, chip = PR number or "open". The open content gives the changes, then the tests to run.

4 · Draft rule
From artifacts.md, section "Tree"
  • Write the tree as ul.tree in a .tree-box. Each li holds <span>name</span>, a data-note and an optional child ul.
  • Use the same tree for each hierarchy, with or without state.
  • Tree lines show only the names. A description goes into the note, not at the right of the name.
  • State: only when the tree is about states. Set data-state (ok, warn, bad) on each li. A colored square shows before the name. Add a .legend above the tree.
  • The script draws one line for each node, with ├─ └─ lines. Each branch folds and opens on its own. A click on a name shows its note under the tree.
  • Lines never wrap. On a narrow screen the tree shrinks down to 50%, then scrolls.
